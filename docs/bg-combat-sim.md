# Симулятор боя BG: покрытие и точность

Как устроен симулятор и как добавить эффект — `src/Hearthpulse.Core/Battlegrounds/Effects/README.md`. Здесь — что он
покрывает, как это мерить и что осталось.

## Метрика

`tools/Hearthpulse.Bench simcover --logs <папка>` (копия данных в `HEARTHPULSE_DATA`):

- **Реальные бои.** Каждая BG-игра из `Power*.log` (на любой глубине) проигрывается через `BattlegroundsTracker` с
  базой карт enUS — тем же путём, что в приложении. Доски и параметры каждого боя (`CombatCapture`, предел урона, Duos,
  первый атакующий) затем считаются заново в трёх режимах бюджета (`SimBudget`; посев от досок, поэтому при том же
  числе прогонов числа повторяются):
  - `Quick` — первый проход на потоке логов (`BattlegroundsTracker.QuickPass`: до 150 прогонов, стоп через 40 мс) — то,
    что оверлей показывает сразу;
  - `App` — фоновый проход приложения (`BattlegroundsTracker.SimOptions`: пока полуширина 95 % интервала победы, ничьей
    и поражения больше 1 п. п., до 10000 прогонов, стоп через 200 мс, не меньше 200; до 2000 прогонов до 19.11.2026) — он
    заменяет первый и попадает в историю;
  - `Full` — 4000 прогонов без ограничения времени: ошибка модели без ошибки малого числа прогонов.

  По каждому режиму: доля боёв без «not simulated», точность исхода и попадание урона (как `BattlegroundsStats.SimAccuracy`
  на странице BG) — с интервалом Уилсона 95 %; Brier по шансам победы/ничьей/поражения (0 — идеально, 0,67 — «всегда
  1/3») со средним ± 1,96·s/√n; затем причины «not simulated» — код (`missing_effect`, `missing_input`, `unknown`;
  `CombatSimulator.Explain`), карта, сторона, зачарования.
- **Сравнение «до и после».** `--out <файл>` пишет оценки по боям; `simcover --before <файл> --after <файл>` сравнивает
  два таких файла **на одних и тех же боях**: по долям — несогласные пары и точный тест Макнемара (двусторонний
  биномиальный), по Brier — парная разность с интервалом. Два перекрывающихся интервала Уилсона на одних и тех же боях
  ничего не говорят о разнице; разные наборы боёв команда сравнивать отказывается.
- **Захваты приложения.** `--captures <папка>` добавляет к боям из логов бои из локальных файлов захватов
  (`<данные>/combat-captures`, раздел «Локальный файл захватов»): те же доски, пометка «not simulated» ставится заново
  сегодняшними таблицами и эффектами. Игра, которая есть и в логах, считается один раз.
- **Реплеи.** `--replays <папка>` считает BG-бои в локальных `.hpr` и для Duos — в скольких боях видны обе доски
  команды. Сами бои из реплеев не симулируются: см. «Реплей как источник боёв».
- **Популярность.** Существа из кэша API (`cache/api/bg-minions-all.json`, `popularity` — доля досок с существом):
  какие из combat-relevant без эффекта и вероятность, что доска (и бой — две доски) без них.

**Пошаговая сверка** — `tools/Hearthpulse.Bench simreplay --logs <папка> [--captures <папка>] [--out <файл>] [--cost <n>]`
(копия данных в `HEARTHPULSE_DATA`): каждый реальный бой со стенограммой проигрывается движком один раз, и каждое случайное
решение берётся из лога — раздел «Пошаговая сверка с логом» ниже.

**Матрица пула** — `Hearthpulse.Bench simmatrix` (копия данных в `HEARTHPULSE_DATA`, снимок данных карт в
`HP_BENCH_BGDATA`) пишет [bg-sim-matrix.md](bg-sim-matrix.md): все виды карт, которые есть в сегодняшней игре, — существа
пула и Timewarped, карты только для Duos, сила героя каждого героя (и силы героя из пула hsbg.cards, с которыми не
начинают: вторая сила от аномалии), тринкеты, тёмные дары, квесты, награды квестов, аномалии, заклинания таверны пула и
заклинания, которые в бою кастуют другие карты, боевые зачарования — с одним из шести статусов (`SimCoverage`:
`no_effect`, `resolved`, `implemented`, `missing_effect`, `missing_input`, `unknown`) и пометкой пула («да» — `in_pool`
API данных v1, для героев и Timewarped — hsbg.cards; «вне пула»; «пул не подтверждён»). Правила те же, что помечают
бой. После патча или нового эффекта — перегенерировать; `SimMatrixTests` сверяет файл с кодом.

Данные текущего патча (с 19.11.2026): `python3 -I tools/effects/fetch_bg_data.py <снимок>` скачивает HearthstoneJSON enUS
(последняя сборка) и библиотеки API данных Hearthpulse v1 (карты, герои, тринкеты, аномалии, квесты, награды, тёмные
дары, Timewarped — с `in_pool`) в папку снимка; из неё строятся все `*.g.cs` эффектов (`gen_combat_relevance.py`,
`gen_player_relevance.py`, `gen_ghastcoiler_pool.py`, `gen_undead_pool.py`; команды — в заголовках скриптов, сборка и
дата данных — в заголовках таблиц) и матрица. Ручные метки существ переносятся из таблицы, новые карты пула — в
`tools/effects/relevance_additions.json`.

История `combat_odds` в `history.db` хранит те же числа по боям, но пересчитать её новым реестром нельзя (доски не
сохраняются). Поэтому меряем на логах.

## Замер (01.11.2026, патч 37.0, логи владельца: 2 BG-игры, 22 боя)

| | До | После |
|---|---|---|
| Бои без «not simulated» | 15 / 22 = 68 % | **21 / 22 = 95 %** |
| Исход угадан (`SimAccuracy`) | 22 / 22 | 22 / 22 |
| Урон в диапазоне | 100 % | 100 % |
| Brier | 0,036 | **0,024** |
| Существа по популярности: доска без неучтённых | ~100 % | 99 % (двое «not in table», ниже) |

Причины «до»: все 7 — Тёмные дары (Offensive/Defensive Sacrifice, Fresh Perspective, Charisma). «После»: тринкет
Blood Golem Sticker (1 бой). После правок ревью (M1, M2, m1) — те же 21 / 22, Brier 0,023; боёв без шансов 0.

**Это выборка разработки, а не проверки.** Карты для реализации выбирались по причинам в этих же 22 боях, поэтому 95 %
— оценка сверху: доверительный интервал для 21 / 22 — примерно 78–99 %, а падение Brier при 22 угаданных из 22 лежит в
пределах шума. Подгонки величин нет (эффекты написаны по тексту карт), но цель «≥ 90 %» нужно подтвердить на новых
логах: повторить `simcover`, когда у владельца будут новые BG-игры, и записать результат сюда.

- **Точность исхода значимо не изменилась** ни в одном режиме (несогласных пар 1–3, p ≥ 0,25).

- **Бюджет почти не влияет**: между 150 и 4000 прогонов Brier 0,138 против 0,132, исход расходится в 2–4 боях из 85.
  Ошибка прогноза — ошибка модели и собственная случайность боя, а не малое число прогонов; уточнение в фоне свою
  работу делает (0,138 → 0,132), на этих 85 боях увеличение бюджета сверх проверенных значений не показало заметного выигрыша.
- **Цель «≥ 90 % без пометки»**: на отложенных 49 боях — 48 / 49, нижняя граница 89,3 %; на всех 85 — нижняя граница
  91,8 %, но 36 из них для S2 не отложенные. Подтверждением на уровне 95 % это ещё не является.
- **Цель «≥ 500 отложенных боёв» не достигнута: на машине 85 боёв, из них отложенных 49.** Игра хранит только последние
  папки сессий: три игры 04.11 из выборки S1 остались только в реплеях, а реплей бой не воспроизводит (ниже). До 500
  отложенных нужно ещё около 450 боёв — при 11–12 боях на законченную игру это примерно 40 BG-игр. Добрать можно двумя
  путями: копировать папки `Logs\Hearthstone_*` после каждой игровой сессии, пока игра их не стёрла, и повторять
  `simcover --logs`; либо просто играть с запущенным приложением — с 15.11.2026 оно сохраняет доски каждого боя
  (раздел «Локальный файл захватов»), и каждая сыгранная игра становится проверочной: `simcover --captures`.

### Реплей как источник боёв (проверено 15.11.2026)

Вопрос: хватает ли локального `.hpr`, чтобы проиграть бой симулятором тем же путём, что приложение. Ответ: **нет**.

Реплей хранит на момент первой атаки (шаг перед первым `M ATTACK` существа; `ReplayFights.Of`, тесты
`SimMeasurementTests`): обе доски слева направо — карта, Атака, Здоровье и урон, золото, ключевые слова, уровень
таверны; героев, силы героя и тринкеты обеих сторон; свою руку; здоровье, броню и уровень таверны по таблице лидеров;
аномалию (в заголовке); первого атакующего. На фикстурной реальной игре и на синтетической характеристики досок реплея
совпадают с `CombatCapture`.

Реплей **не** хранит остальное, из чего состоит захват (`ReplayFights.Missing`), и грамматика формата
(`BattlegroundsReplayGrammar`: закрытый список типов карт и тегов) этого не допускает:

- зачарования на существах (Тёмные дары, выданные хрипы) — `SimMinion.Enchantments`; без них не работает правило «not
  simulated» для зачарований и эффекты `deaths/DarkGifts.cs`;
- выданные метки `DEATHRATTLE` / `AVENGE` / `BACON_RALLY` — `SimMinion.Mechanics`;
- `TAG_SCRIPT_DATA_NUM_1/2` существ (размер Жука, бонус Лобстера…) — `SimMinion.ScriptData1/2`;
- `CREATOR` (копия от силы героя уже на доске) — `SimMinion.CreatorCardId`;
- существа, убранные триггером начала боя, — `SimMinion.Remembered`;
- выданный тип существа (`CARDRACE`) — `SimMinion.Tribes`;
- числовые теги игроков — `SimSide.Tags`; величины своей силы героя и тринкетов — `SimSide.ExtraTags`;
- предел урона лобби (`BACON_COMBAT_DAMAGE_CAP`) — `SimOptions.DamageCap`; Божество лобби — `SimSide.Extras`.

Бой, собранный из реплея без этих полей, симулировался бы не так, как в приложении, и занижал бы долю «not simulated»
(пометка по зачарованиям и выданным хрипам просто не ставилась бы), поэтому `simcover --replays` бои только считает.
На машине владельца: 26 реплеев, из них 6 BG (76 боёв — это выборка S1 целиком: 04.11 и 05.11), Duos нет.

Поэтому доски сохраняются отдельно от реплея — следующий раздел. Формат `.hpr` не менялся.

### Локальный файл захватов (15.11.2026)

Приложение сохраняет бои каждой законченной BG-игры в `<данные>/combat-captures/<начало игры>-<хэш>.hpc` (gzip JSON,
`Tracking/CombatCaptureStore.cs`). Файл **никуда не отправляется**: его не читает ни загрузка в профиль, ни общий пул,
ни запись источника, ни реплей (и ссылка на него), ни отчёт о сбое; выключателя нет, потому что отправлять нечего.
С 19.11.2026 (источник v3) журнал игры несёт свою копию тех же боёв из памяти — без руки, по белому списку, под
переключателем записей игр ([source-capture.md](source-capture.md), «Battlegrounds fights»); это вход для замера на
≥ 500 отложенных боёв: выгрузка владельца `server/pool/node/export-combats.mjs` → `simcover --pool <файл>` (те же
оценки, что у `--captures`; эффекты, читающие руку игрока, играют без неё).
`CombatCaptureStoreTests` падает, если о файле узнаёт ещё один исходный файл или если файл, который что-то отправляет
по HTTP, оказывается среди знающих.

Что в файле, по каждому бою, на момент первой атаки:

- ровно вход `CombatSimulator`: обе стороны (`SimSide` — существа со статами, ключевыми словами, зачарованиями,
  `TAG_SCRIPT_DATA_NUM_1/2`, `CREATOR`, убранными существами; герой, сила героя, карты уровня игрока, числовые теги
  игрока, величины своих карт, уровень таверны, здоровье, ход; существа своей руки), кто атаковал первым, предел
  урона, считается ли урон (в Duos — нет);
- что лог сказал о каждом существе доски сверх этого (`MinionFacts`: id карты как в логе и метки эффектов) — чтобы
  пометку «not simulated» можно было поставить заново с новыми таблицами и эффектами (`BattlegroundsTracker.IsUnsimulated`);
- что случилось: исход, урон полученный и нанесённый; и прогноз приложения на момент сохранения игры (`CombatOdds`);
- с формата 2 (19.11.2026) — стенограмма боя: видимый ход боя после захвата (раздел «Пошаговая сверка с логом»).

Только то, что видел игрок, плюс одно послеигровое раскрытие: файл пишется после игры, и у соперника в
`SimSide.HiddenTags` лежат его числовые теги игрока, которых клиент не показывает (см. «Входы симулятора» ниже); в живой
симулятор они не попадали. Рука и секреты соперника не попадают никуда.
Имён, BattleTag, идентификаторов аккаунта и рейтинга в файле нет — карты по id; в заголовке время начала игры, сборка
клиента и признак Duos.

Ограничения: 500 игр и 32 МБ на папку (игра — 7–12 КБ, в формате 2 со стенограммами и входами — около 15 КБ, так что
на деле работает предел по числу игр), старые игры
вытесняются первыми, по времени начала игры; файл пишется целиком под временным именем и переименовывается. На потоке
логов делается только список ссылок на уже построенные неизменяемые записи (в конце игры) и по одной маленькой записи
на существо при захвате; упаковка и запись — на потоке пула после записи игры в историю. Сбой записи пишется в лог и
ничего не ломает; битый, обрезанный, слишком большой (16 МБ после распаковки) или чужой версии файл читается как
«нет файла». Отдельно цена на потоке логов не измерялась (по чтению кода, не замером).

Проверка на реальных играх (15.11.2026): копия логов проиграна через `GameSession` (Bench `replay`) — записано 7
файлов (82 боя; восьмая игра на момент копии не закончена и в историю не попала). `simcover --captures` дал по этим
82 боям побитно те же шансы, пометки и Brier, что `simcover --logs`, во всех трёх режимах; при `--logs` и `--captures`
вместе все 7 игр опознаны как уже посчитанные.

Чего файл не даёт: истории до 15.11.2026 (старые `combat_odds` по-прежнему не пересчитать) и игр, сыгранных без
запущенного приложения. Импорт игр из сохранённых логов (`LogBackfill`) захваты не пишет.
### Входы симулятора: точные и оценённые (19.11.2026, пакет I)

Во время игры — только то, что видит игрок (`docs/adr/0005-hidden-information.md`).

- **Точно из лога, обе стороны** (на экране у обоих): доски, зачарования существ с их числами
  (`SimMinion.EnchantmentValues`), смерти в Start of Combat до захвата (`SimSide.DeathsBeforeCapture`, у существа —
  `FriendlyDeathsBeforeCapture`). Отсюда же прогресс пробуждения Deity соперника: смерти его Аберраций видны на доске,
  поэтому он точный. Общие для лобби вещи тоже точные: аномалия, какое Deity, племена лобби (из памяти клиента).
- **Точно, только свои**: теги своего игрока, свои зачарования игрока (`SimSide.PlayerEnchantments`: остаток призывов
  Diremuck `BG27_556pe`, бонус Жуков `BG31_808pe`), величины своих карт игрока (`ExtraTags`: флаг копии
  Stormpike/Frostwolf и др.), рука без карт с «Unplayable» `BG26_350e2`.
- **Оценка у соперника** (`SimSide.Estimates`, `CombatOdds.Estimated`, `CombatSimulator.ExplainEstimates`; это не
  «not simulated», эффект работает): значения Кровавых самоцветов, бонус таверных заклинаний, статы Deity, размер Жука —
  даже если они есть в логе. Оценка — наша величина как ориентир, иначе напечатанная; появляется только при карте,
  которая её читает. Если племена лобби не прочитаны — оценка «весь пул» для Ghastcoiler.
- **После игры**: `BattlegroundsTracker.Captures` после конца игры кладёт настоящие значения соперника в
  `SimSide.HiddenTags` и ставит `SimOptions.PostGame`; `CombatSimulator.Run` с этим флагом (или `SimInputs.PostGame`)
  подставляет их вместо оценок. Живой трекер флаг не ставит (`SimInputsTests`).

## Скорость и число прогонов (19.11.2026)

`tools/Hearthpulse.Bench simperf --logs <папка> [--captures <папка>] --rounds 3` (копия данных в `HEARTHPULSE_DATA`).
Корпус — бои логов и захватов, как у `simcover`, и семь синтетических худших случаев: цепочки предсмертных хрипов,
полные доски, золотые с Reborn, Avenge, cleave с Windfury, Battlecry в бою (эффекты пакета E2), затяжной бой.
Команда печатает:

- бои в секунду, нс и байты на бой на одном потоке и на 2–16 потоках;
- быстрый и фоновый проход так, как их делает приложение: время (p50, p95, max), процессорное время, число
  прогонов и полуширину 95 % интервала (Уилсон) самой неточной из долей победы, ничьей и поражения;
- те же проходы на 1, 2, 4 и 8 потоках;
- «ёмкость» — сколько прогонов влезает в 40 и 200 мс без потолка числа прогонов.

`HP_BENCH_ONLY=throughput|passes` оставляет только одну часть: так удобно чередовать «до» и «после» на загруженном
ПК. `HP_BENCH_PROFILE=n` — n секунд боёв на одном потоке: к процессу можно подключить `dotnet-trace`, и команда
печатает выборку аллокаций по типам.

**Как устроены прогоны** (`CombatSimulator.Runs.cs`):

- Прогоны идут чанками по 50 (`ChunkRuns`). У каждого чанка своё зерно (`ChunkSeed` от зерна досок и номера чанка)
  и свой выборщик (`RandomChooser` на этом зерне): бои чанка не зависят от других чанков.
  Результаты складываются строго по порядку номеров, поэтому шансы зависят только от досок и числа прогонов, а не от
  числа потоков и порядка их работы.
- Время, отмену и точность проверяют между чанками. Бюджет времени и отмена оставляют в счёте префикс чанков.
- Остановка по точности (`SimOptions.TargetHalfWidth`): после `MinRuns` проход останавливается на первом чанке, где
  полуширина каждой доли не больше цели. Чанки, досчитанные другими потоками после этой точки, отбрасываются.
  Достигнутая полуширина — `CombatOdds.HalfWidth`.
- Потоки — это вызывающий поток и до `Parallelism − 1` помощников из пула. Помощник, которого пул запустил поздно,
  сразу выходит. Вызывающий поток ждёт только помощников, которые сейчас считают чанк, свободного потока пула не ждёт.

**Решения по замеру** (машина 5950X; таблицы и чередующиеся замеры — `perf-baseline.txt` в папке задачи
`TASK-2026-11-19-sim-all-mechanics`):

- **Быстрый проход** — как был: до 150 прогонов, 40 мс, один поток. В два потока p95 падает с 2,2 до 1,7 мс на реальных
  досках и с 6,5 до 3,8 мс на синтетике. Оба значения далеко от 40 мс, а ядра сразу после этого нужны фоновому
  проходу.
- **Фоновый проход:** до ±1 п. п., не больше 10000 прогонов и 200 мс, не меньше 200 прогонов, потоков — половина
  логических процессоров, но не больше четырёх (`SimOptions.BackgroundParallelism`). На реальных досках (A/B с
  `main` 44e706f4):

  | | до | после |
  |---|---|---|
  | прогонов | 2000 | 200–9600 (в среднем 2376) |
  | полуширина, средняя / худшая | 0,67 / 2,19 п. п. | 0,96 / 1,00 п. п. |
  | время p50 / p95 | 12 / 27 мс | 1,3 / 31 мс |
  | процессор на проход | 13 мс | 27 мс |

  Однобокий бой останавливается на минимуме, близкий считается до ±1 п. п. В один поток близкие бои упираются в
  200 мс (p95 137 мс). На 8 потоках p95 23 мс против 32 мс на четырёх, но процессора уходит на 40 % больше.
- **Масштаб по потокам** (2000 прогонов на доску): ×1,8 на двух, ×3,5 на четырёх, ×4,9 на восьми, ×7,2 на
  шестнадцати. Рост держат сборки мусора (около 6 КБ на бой): что убрать в `Simulation/*`, записано в
  `perf-proposals.md` рядом с карточкой задачи. Пока этими файлами владеет пакет P1, правок там нет.
- Однопоточная скорость движка и накладные расходы на вызов не изменились (чередующийся A/B: около 245 000
  реальных боёв в секунду). На бой стало на 142 байта меньше: урон считается без итераторов
  (`DamageRules.DamageOfTiers`).

Шансы при том же числе прогонов теперь другие, чем до 19.11: поменялся поток случайных чисел (зерно на чанк). Смысл
чисел прежний.

**Не измерено:** медленный ПК (2–4 логических процессора), игра, запущенная рядом с симуляцией, Linux и macOS.

## Пошаговая сверка с логом (simreplay, 19.11.2026)

Исход и урон проверяют бой целиком; `simreplay` проверяет каждый шаг. Три части:

- **Решения движка.** Каждый случайный выбор в `Simulation/*` и `Effects/**` идёт через один интерфейс
  `ICombatChooser` (`Simulation/CombatChooser.cs`) с видом решения `ChoiceKind` (`FirstAttacker`, `AttackTarget`,
  `RandomTarget`, `TieBreak`, `StatSplit`, `RandomSummon`, `RandomCard`, `RandomHandCard`, `HandTieBreak`), источником
  (кто решает) и явным списком кандидатов. Шансы считает `RandomChooser` на посеве боя: один `Random.Next` на решение;
  ничья из N кандидатов тянет те же N − 1 чисел, что прежний выбор «на лету», — сценарии тестов с `picks` прежние.
  Изменился порядок вызовов в одном случае: прежний `Best` тянул число и для ничьей со значением, которое потом
  перебивал больший ключ; теперь тянет только для итоговой ничьей. Это малый сдвиг шансов при том же посеве (по 3 прогонам
  на 85 боях не замерялся отдельно). `SimReplayTests` падает, если в `Effects/**` или `Simulation/*` кто-то обращается к
  `Random` мимо `CombatChooser.cs`.
- **Стенограмма боя.** `BattlegroundsTracker` (`BattlegroundsTracker.Transcript.cs`) после захвата досок на первой
  обычной атаке пишет видимый ход боя до его конца: атаки (атакующий, защитник из `PROPOSED_DEFENDER`, вложенная или
  обычная), урон (изменение `DAMAGE`), смерти, призывы (id карты как в логе, золотой, сторона, позиция), изменения
  `ATK`/`HEALTH` и ключевых слов существ доски (и существ своей руки), сработавшие эффекты (`TRIGGER`/`POWER` с
  источником: существо, сила героя, тринкет, награда, зачарование на существе, карта своей руки) и обе доски перед
  каждой обычной атакой и в конце. Конец боя: атака героя; возврат своей доски таверны (`SETASIDE` → `PLAY`, когда одна
  из досок пуста — ничья); первая уборка существа с доски; конец боя по `BOARD_VISUAL_STATE`. Рука и скрытые сущности
  соперника не пишутся (тест `The_opponents_hand_never_reaches_a_transcript`). Вложенность считается от глубины блоков
  на первой атаке: реальные логи оставляют блоки `PLAY` таверны без `BLOCK_END` при смене списка задач клиента, и стек
  парсера между боями не пуст. Стенограмма хранится в захвате (`CapturedFight.Transcript`) и в файле захватов: формат 2
  (`CombatCaptureStore.FormatVersion`), стенограмма версии 1 (`CombatTranscript.CurrentVersion`); файлы формата 1
  читаются без стенограмм, стенограмма незнакомой версии отбрасывается, бой остаётся. Формат 2 хранит и входы стороны,
  которые записи держат вне JSON (пакет I: значения зачарований, смерти до захвата, зачарования игрока — только свои,
  племена лобби, оценки), блоком `OursInputs`/`TheirsInputs` рядом со стороной; при чтении они возвращаются на сторону,
  `HiddenTags` = null читается как пустой, а сохранённый бой считается с `SimOptions.PostGame` (после игры).
- **Проигрыватель** (`tools/Hearthpulse.Bench/Sim/SimReplay.cs` и `TranscriptChooser*.cs`, общие с тестами). Бой со стенограммой идёт один раз с
  `TranscriptChooser`: существа сопоставляются по id сущности лога (захваченные — своими, призванные — n-й призыв той же
  карты на той же стороне в симе = n-й в логе); цель атаки — защитник из лога; выбор эффекта — сущность, которую
  изменил эффект того же источника в этой атаке (иначе — где угодно в этой атаке); карта пула — призыв из лога. Перед
  каждой обычной атакой и в конце доски сравниваются с логом. Первое расхождение боя: номер атаки, сущность, поле,
  ожидаемое и фактическое, эффекты вокруг и правило: `AttackerOrder`, `Target`, `Damage`, `Keyword`, `DeathOrder`,
  `SummonPosition`, `Aura`, `Trigger`, `Other`. Выбор, на который лог не отвечает (или отвечает кандидатом, которого
  сим не предлагал), — тоже расхождение. `HP_REPLAY_DUMP=<конец ключа боя>` печатает стенограмму, доски и трассу боя.
  Бои без атаки существа (одна доска пуста) стенограммы не получают и не считаются.
- **Цена.** Замер 19.11.2026 (`simreplay --cost 5`, Release, лог 15.11.2026: 5 игр, 58 боёв со стенограммой): чтение
  лога трекером на потоке логов — медиана 569 мс без стенограмм и 598 мс с ними (+29 мс на весь лог, около 0,5 мс на бой;
  прежние замеры давали разницу от −89 до +197 мс — шум общего ПК), выделения +1,5 МБ на весь лог (26 КБ на бой, 52
  события и 10 досок в среднем). Файл захватов — 14,7 КБ на игру со стенограммами против 8,7 КБ без (5 игр): при 500
  играх около 7 МБ, предел 32 МБ папки не достигается. Скорость движка после перевода решений на `ICombatChooser`: 150
  случайных досок × 2000 боёв, три попеременных прогона по пять кругов — база 3,4–4,3 с, ветка 3,3–4,0 с (разницы не
  видно). Шансы на 60 боях выборки (`simcover --before/--after`, три бюджета, до слияния с E*/I): 9 из 180 пар
  изменились, наибольший сдвиг победы 1,3 п. п.; доля «без not simulated», попадание исхода и урона не изменились,
  разность Brier ≈ 0.
- **Реальный бой → тест.** `tests/Hearthpulse.Tests/Sim/SimReplayKit.cs`: `Fights(lines, day, cards)` и
  `AssertReplays(fight, cards)`; пример — `The_kept_real_fight_replays_step_by_step_without_a_divergence` на
  `Fixtures/BattlegroundsGame`.

Базовый замер (19.11.2026, правила движка до пакета R; в main уже P0, E1, E2, E4, I, U; лог 15.11.2026, 58 боёв со
стенограммой, стороны после игры): **36 / 58 = 62,1 %** боёв проигрываются до конца без расхождений (Уилсон 95 %:
49,2–73,4 %); первые расхождения — `AttackerOrder` 10 (в основном токен или копия Reborn в слоте погибшего атакует раньше,
чем по правилу «разрыва»), `SummonPosition` 5, `Trigger` 5 (три — сила героя BG22_HERO_003p копирует существо, а в логе
не срабатывает), `Keyword` 1, `Aura` 1. Отчёт по боям: `reference/tasks/TASK-2026-11-19-sim-all-mechanics/replay-baseline.txt`
(вне репозитория).

Карта из таблицы с `Relevant` без эффекта теперь честно делает бой «not simulated» (раньше силы героя и тринкеты не
считались вовсе). Bewitched Ribbon (+2/+2 после заклинания в бою) — есть эффект.

**Полная разметка карт игрока.** Ручная таблица держит силы героев из списка API и тринкеты, найденные вручную.
Остальные карты игрока — все силы героя, тринкеты с золотыми версиями, награды квестов, аномалии из HearthstoneJSON,
729 строк — размечены скриптом по английскому тексту (`tools/effects/gen_player_relevance.py` →
`PlayerCardRelevance.g.cs`). Правило по предложениям: боевой триггер (союзник атакует, умирает, получает урон, теряет
ключевое слово, призван, «Avenge», «each combat», аура «your minions have +X», «your Deathrattles») и действие,
меняющее бой (give, summon, deal, destroy, trigger, кровавый самоцвет, ключевое слово); награда в таверне (get,
Discover, золото, обновление) — нет; только «Start of Combat» — `Resolved`. На ручной таблице текст совпал в 46 из 48
карт (Fang Anklet и Bewitched Ribbon — ручная разметка главнее). Скрипт нашёл 10 боевых тринкетов (11 id), которых не было в
ручной таблице (Boom Controller, Twin Sky Lanterns, Crocheted Sungill, Mama Bear Sticker, Jar o' Gems, Kaboom Bot и
Impulsive Portrait, Mug of the Sire, Cyclist Portrait, Snarky Portrait): без эффекта они теперь делают бой «not
simulated».

**Честное значение по умолчанию.** Карта игрока, которой нет ни в одной таблице, — новее данных: её действие
неизвестно, и бой считается «not simulated» (`CombatSimulator.Unsimulated`), а не симулированным молча. После патча
таблицу перегенерировать из свежего `cards.enUS.json`. Замер `simcover` после этого (2026-11-02): по-прежнему 21 / 22 =
95 %. Первый прогон дал 77 %: трекер считал тринкетом зачарование тринкета (`BG32_MagicItem_362e`, по `_MagicItem_` в
id) — теперь зачарования, заклинания и существа с таким id тринкетами не считаются (`IsTrinket`).

### Заклинания в бою (E1, 19.11.2026)

Tidecaller срабатывает до блока POWER заклинания, слева направо; после каждого заклинания — из руки или кастованного

руки, — есть). Поэтому камни идут через `Fight.PlayBloodGem` (их видит Geomagus Roogug), а не через `CastSpell`.

## Правило «not simulated» для зачарований

Каждая выданная метка (хрип, Avenge, Rally: есть у существа, нет в карте) должна быть объяснена зачарованием: строкой
таблицы для этой же метки (дар «только таверна» или дар с эффектом) или зачарованием с эффектом вне таблицы. Иначе
существо помечается. Например, Charisma (раж в таверне) не объясняет хрип от другого зачарования. Помечается всегда,
если на существе зачарование из таблицы с `Relevant` без эффекта (`CombatRelevance.IsUnsimulated`).
